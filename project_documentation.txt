1. PROJECT OVERVIEW
================================================================================

SandboxPlaywright is an enterprise-grade test automation framework designed for
end-to-end testing of insurance platform workflows (OneShield). It supports UI
and API testing within a single unified pytest project.

Key goals:
  - Reliable cross-browser UI automation via Playwright
  - Human-readable test scenarios via pytest-bdd (Gherkin)
  - Clean data separation via JSON test data files
  - Rich reporting via Allure + pytest-html
  - Consistent execution locally and in Docker containers
  - Credential safety in both logs and Allure reports

3. ARCHITECTURE
================================================================================

The framework is built on three complementary design patterns:

  POM (Page Object Model)
    - Every application page is a Python class under ui/pages/
    - All locators and interactions are encapsulated inside the page class
    - All pages inherit from BasePage (ui/pages/common/base_page.py)

  BDD (Behavior-Driven Development)
    - Tests are written in Gherkin (.feature files under ui/features/)
    - Step definitions are Python functions under ui/steps/
    - pytest-bdd wires them together; test entry points live in ui/tests/

  DDT (Data-Driven Testing)
    - Test data lives in JSON files under testdata/static/
    - A TC_ID value in the Gherkin scenario selects the correct data row
    - The test_data dict is injected via pytest fixtures


  High-Level Request Flow:
  ┌──────────────────┐
  │  .feature file   │  (Gherkin scenario)
  └────────┬─────────┘
           │ parsed by pytest-bdd
  ┌────────▼─────────┐
  │ Step Definitions │  (ui/steps/)
  └────────┬─────────┘
           │ page fixtures via DI
  ┌────────▼─────────┐
  │  Page Objects    │  (ui/pages/)
  └────────┬─────────┘
           │ extends BasePage
  ┌────────▼─────────┐
  │  Playwright API  │
  └────────┬─────────┘
           │
  ┌────────▼─────────┐
  │    Browser       │  (Chromium / Firefox / WebKit / Chrome / Edge)
  └──────────────────┘

5. ENVIRONMENT CONFIGURATION
================================================================================

The framework reads from a .env file at startup via dotenv.load_dotenv().

Required keys:

  PARTNER_NUM=0
  USERNAMEE=your_username
  PASSWORD=your_password

Notes:
  - USERNAMEE uses double E to avoid clashing with the Windows USERNAME variable
  - .env is listed in .gitignore and must never be committed
  - For Docker: pass the file with --env-file .env or env_file in compose

6. TEST EXECUTION
================================================================================

Local execution:

  pytest                          Run all tests (uses pytest.ini addopts)
  pytest -m auto                  Run auto-marked tests
  pytest -m validation            Run validation-marked tests
  pytest -m api                   Run API tests
  pytest -m smoke                 Run smoke tests
  pytest -m auto -n 4             Run auto tests with 4 parallel workers

Browser options:

  pytest --browser=chromium       Default (Playwright bundled Chromium)
  pytest --browser=chrome         System Google Chrome
  pytest --browser=msedge         System Edge
  pytest --browser=firefox
  pytest --browser=webkit
  pytest --headed                 Show browser window
  pytest --slow-mo=100            100 ms delay between actions
  pytest --pw-trace=on            Enable Playwright trace recording

Active markers (defined in pytest.ini):

  auto, homeowner, smoke, regression, login, validation, api, empty-fields,
  invalid-credentials, format-validation, whitespace,
  case-sensitivity, length, security, ui, navigation, error-messages,
  special-chars, format, edge-case, accessibility, post-login

  - On-failure: PNG screenshot (attached in-memory, no file write)
  - On smart wrapper failure: JSON element metadata attachment
  - Masked Allure parameters for username and password fields

8. CREDENTIAL SAFETY
================================================================================

Two layers of protection exist:

  1. Log masking (utils/logger.py)
     -  _CredentialMaskFilter is attached to every logger instance
     -  Reads USERNAMEE and PASSWORD from env at first log write
     -  Replaces any occurrence of those values in message text with ***

  2. Allure parameter masking (ui/steps/common/login_validation_steps.py)
     -  Uses allure.dynamic.parameter(..., mode=ParameterMode.MASKED)
     -  Requires import from allure_commons.types import ParameterMode
     -  NOTE: allure.mask_parameters() does not exist in the Python library

9. DOCKER
================================================================================

Build image:
  docker build -t playwright-tests:latest .

Run a specific suite with .env credentials:
  docker run --rm --env-file .env playwright-tests:latest pytest -m auto -n 4 -v

Note: direct docker run loses artifacts when the container exits. Use Compose
for persistent output volumes.


================================================================================
10. DOCKER COMPOSE
================================================================================

Services defined in docker-compose.yml:

  Service            Marker          Workers    Notes
  ----------------   ----------      -------    ---------
  tests-auto         -m auto         -n 4
  tests-validation   -m validation   -n 5
  tests-api          -m api          none

Each service:
  - Builds from Dockerfile
  - Loads .env via env_file
  - Mounts reports/, allure-results/, screenshots/, logs/ as host volumes

Run commands:

  docker compose run --rm tests-auto
  docker compose run --rm tests-validation
  docker compose run --rm tests-api

Windows CMD sequential:
  docker compose run --rm tests-auto & docker compose run --rm tests-validation

IMPORTANT:
  - Use --rm (double dash). Single dash -rm will error.
  - Semicolon ; does not work in Windows CMD. Use & instead.

12. KNOWN ISSUES & SOLUTIONS
================================================================================

Problem: AttributeError: module 'allure' has no attribute 'mask_parameters'
Fix:     Use allure.dynamic.parameter("field", value, mode=ParameterMode.MASKED)
         with: from allure_commons.types import ParameterMode

Problem: unknown shorthand flag: 'r' in -rm
Fix:     Use --rm (two dashes): docker compose run --rm <service>

Problem: exec: ";": executable file not found in $PATH
Fix:     Use & in Windows CMD, or run commands on separate lines

Problem: Credentials appear in logs or Allure
Fix:     - Confirm _CredentialMaskFilter is active in utils/logger.py
         - Confirm allure.dynamic.parameter masking is in login step definitions
         - Confirm .env is being loaded (dotenv loaded in conftest.py)

Problem: Allure report not generated
Fix:     Run: allure serve allure-results
         Or:  allure generate allure-results --clean -o allure-report
