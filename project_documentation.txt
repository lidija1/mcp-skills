1. PROJECT OVERVIEW
-------------------
SandboxPlaywright is an enterprise-grade test automation framework designed for
end-to-end testing of complex insurance workflows. The framework is built on
Python, utilizing Playwright for browser automation and pytest-bdd for 
Behavior-Driven Development. 

Recent architectural updates have transitioned the framework to a "JSON-First" 
data model and unified the Page Object Model (POM) into a logical application-based 
structure, removing legacy complexities.

2. TECHNOLOGY STACK
-------------------
- Core: Python 3.x, Playwright (Sync API)
- Test Runner: pytest
- BDD: pytest-bdd
- Reporting: Allure Framework
- Data Management: Native JSON (Primary), pandas/openpyxl (Legacy Excel)
- Path Handling: Pathlib (for cross-environment reliability)
- Environment Config: python-dotenv

3. ARCHITECTURE & DESIGN PATTERNS
---------------------------------
3.1 Unified Page Object Model (POM)
The framework follows a strict POM, organized by functional modules:
- Common: Shared components (Login, Customer Creation)
- Auto: Insurance-specific workflow pages (Vehicle, Driver, Coverage)

3.2 Data-Driven Testing (DDT)
Data is decoupled from scripts. The framework supports highly performant JSON 
loading which maps directly to Python dictionaries, integrated into the 
pytest-bdd fixture lifecycle.

3.3 Modern Locator Strategy
Page objects prioritize native Playwright locators (ByRole, ByText, ByLabel) 
ensuring tests are resilient to DOM changes compared to brittle XPaths.

5. DATA MANAGEMENT (JSON STANDARDS)
-----------------------------------
The framework now utilizes CamelCase naming conventions in JSON to align with 
modern API and data standards.
- Entry point: `testCases` array.
- Key Mapping:
    - Primary: `FirstName`, `LastName`, `DOB`, `VehicleUse`.
    - Format: Strings (to handle leading zeros in ZIPs/Phone Numbers).
- Advantage: Performance is significantly higher than Excel-based parsing, 
  and data is easily searchable via IDE.

6. TEST EXECUTION & MARKERS
---------------------------
Execution is marker-driven:
- `@smoke`: Critical core paths.
- `@auto`: Full Personal Auto regression.
- `@login`: Targeted authentication tests.

Command Example: `pytest -m smoke --headed`

7. REPORTING (ALLURE)
---------------------
Rich reporting is integrated via `pytest.ini`. Reports include:
- Visual step-by-step breadcrumbs.
- Automatic failure screenshots.
- Embedded logic logs (DEBUG level in files, INFO in reports).
- Execution data parameters matching the JSON record.

Serve Report: `allure serve allure-results`
